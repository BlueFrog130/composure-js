The Dev Loop is configured in one typed option, `composure({ dev: { application, guild, tunnel } })`, and is off without `dev`. `application` names the Dev Application, the only one ever repointed, and only when `DISCORD_TOKEN` is its token (otherwise the URL to set by hand is printed); `guild` turns on dev Sync. `tunnel` is `"quick"` (the default), `{ name, hostname }` for a named Cloudflare Tunnel the plugin runs (token from `CLOUDFLARE_TUNNEL_TOKEN` or `cloudflared tunnel login`, with a warning when its route misses Vite's port), `{ url }` for a tunnel you already run, a function `(port) => Promise<Tunnel>`, or `false`; Vite's `server.allowedHosts` allows exactly that tunnel's host. Settings are never read from the environment: it holds only the secrets `DISCORD_TOKEN`, `DISCORD_PUBLIC_KEY` and `CLOUDFLARE_TUNNEL_TOKEN`, the Dev Application's in `.env.local` and production's in `.env.production.local`.

The quick tunnel is accepted by Discord within seconds: it counts as ready once trycloudflare.com's authoritative nameservers publish its hostname, and nothing looks the hostname up before then, so no resolver (Discord's included) caches it as missing. The endpoint is set once the App answers through the tunnel; a 429 waits `retry_after`, and a rejected endpoint says whether `DISCORD_PUBLIC_KEY` is another application's. Each stage logs one line with the elapsed time and has its own limit (connect 30 s, DNS 60 s, probe 30 s); a failure names its stage without stopping `vite dev`. `untun` is no longer a dependency.
