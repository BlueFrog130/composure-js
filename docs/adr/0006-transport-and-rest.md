# REST goes through an injectable Transport; rate limits are reactive

The Interaction Client (`c.client`, authorized by the Interaction token) and Bot Client (`c.bot`, bot token; a type error and a throw without one) send every request through a `Transport`: one function from a request to a response, `fetch` by default, so no HTTP library is bundled and tests inject `MockTransport`, which records requests and answers from a queue (composure-rs ADR 0004). Core encodes bodies (JSON, or multipart when a View carries files) so a Transport only moves bytes. Rate limiting is reactive only: a 429 is waited out when `retry_after` is under a cap (about 2s at runtime, 60s for Sync), otherwise `RateLimitedError` is thrown; isolates share no memory, so per-bucket tracking would mostly be cold. Endpoints are tree-shakable functions or per-resource subpaths of `composurejs/rest`, hand-written over the types generated from the spec (ADR 0003). REST message bodies (create message, follow-up, edit, execute webhook) accept a View, rendered and validated exactly as an Interaction response is. Logs name the method and route template, never the URL, which can hold an Interaction token.
