# REST goes through an injectable Transport; rate limits are tracked per isolate

The Interaction Client (`c.client`, authorized by the Interaction token) and Bot Client (`c.bot`, bot token; a type error and a throw without one) send every request through a `Transport`: one function from a request to a response, `fetch` by default, so no HTTP library is bundled and tests inject `MockTransport`, which records requests and answers from a queue (composure-rs ADR 0004). Core encodes bodies (JSON, or multipart when a View carries files) so a Transport only moves bytes. Rate limiting is reactive only: a 429 is waited out when `retry_after` is under a cap (about 2s at runtime, 60s for Sync), otherwise `RateLimitedError` is thrown; isolates share no memory, so per-bucket tracking would mostly be cold. Endpoints are tree-shakable functions or per-resource subpaths of `composurejs/rest`, hand-written over the types generated from the spec (ADR 0003). REST message bodies (create message, follow-up, edit, execute webhook) accept a View, rendered and validated exactly as an Interaction response is. Logs name the method and route template, never the URL, which can hold an Interaction token.

As built (milestone 5), Endpoints are plain functions in `composurejs/rest` that take the client first: `createMessage(c.bot, channelId, <Report />)`, `addMemberRole(c.bot, guildId, userId, roleId, { reason })`. Methods on `c.bot` were rejected because a bundle could not drop the ones it never calls. Each function's path, method and operationId are declared once in `ROUTES`, and its body, query and response types come from that operationId in `src/rest/schema.d.ts`. That file is generated from the vendored spec (`spec/openapi.json`, pinned in `spec/PINNED`, refreshed by `scripts/update-spec.mjs`), is type-only, and is about 670 KB of declarations that never reach a bundle. openapi-typescript drives the TypeScript 5 compiler API, which TypeScript 7 no longer ships, so the script runs it with TypeScript 5.9 through `pnpm dlx`; the repo itself stays on TypeScript 7. `test/rest-spec.test.ts` checks every `ROUTES` entry's method, path and operationId against the spec, checks that each `OUT_OF_SCOPE` prefix (gateway, OAuth2 and user-token routes, Partner SDK, Social SDK lobbies) still exists, and with `PRINT_UNIMPLEMENTED=1` lists what is left. Tier 1 is implemented: channels, messages, pins, reactions, guilds, members, bans, roles, webhooks and users. The Interaction Client (`c.client`) needs no bot token and wraps the webhook routes for the original response and follow-ups (`followup(Ephemeral(..))`) plus the callback endpoint, which also carries answers with files. Its `editOriginal` retries a 404 for up to about 4 seconds. Message bodies are rendered once into a branded `MessageBody` (JSON, `attachments`, files), so the pipeline can check what a body places before sending it. `c.bot` throws a `CredentialsError` naming `DISCORD_TOKEN` when the Credentials have no token. The clients are classes the Context's getters construct, so they are in every bundle that uses Context; the Endpoints are not.

**Resilience** (added later). Each attempt is bounded by a timeout (10 s, `RestOptions.timeout` / `AppOptions.requestTimeout`), enforced by aborting the request and by racing it, since a Transport may ignore the signal; it throws `RequestTimeoutError` naming the route template. Requests whose method is safe to repeat (GET, PUT, PATCH, DELETE) are retried twice, after 250 ms and 1 s, on a network error, a timeout or a 500/502/503/504; a POST never is, because a create that reached Discord before the connection failed would happen twice. Rate limits are no longer only reactive: each response's `X-RateLimit-Bucket`, `-Remaining` and `-Reset-After` are recorded per isolate, keyed by authorization, bucket and major parameters (channel, guild, webhook), so a request to a used-up bucket waits for its reset first, and throws `RateLimitedError` without sending when that wait exceeds `maxRateLimitWait`. State lives at module scope, like the imported public key, so it survives across requests in one isolate and costs nothing across isolates; expired buckets are dropped once more than 500 are tracked, since every Interaction token is its own webhook bucket. Rejected: a shared rate limit store (Durable Object, Redis), which would make core depend on a platform, and retrying POSTs with an idempotency key, which Discord does not offer. The User-Agent names the package version, set at build.
