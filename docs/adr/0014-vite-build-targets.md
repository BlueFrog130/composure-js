# `vite build` per target; Cloudflare composes with @cloudflare/vite-plugin

Inline Handlers only work in a build that runs `@composurejs/vite` (ADR 0005), so Vite is how a bot is built, not just how it is tested. `composure({ target })` sets the build up, as `@hono/vite-build` does for Hono. `target: "node"` and `"bun"` turn `vite build` into an SSR build of the server entry (default `src/node.ts` / `src/bun.ts`). The output is one ES module, `<outDir>/index.js`, with every dependency bundled (`ssr.noExternal: true`) and only built-ins external (`node:*`, plus `bun:*` for Bun), so deploying is copying one file and running `node dist/node/index.js`. They are not minified, which keeps server stack traces readable. `target: "cloudflare"` does not replace `@cloudflare/vite-plugin`, which builds the Worker from `wrangler.jsonc`, writes the deployable `wrangler.json` beside it, and runs `vite dev` on workerd; the composure plugin hoists in the Worker environment like any other. A Cloudflare build without that plugin fails at config time saying to add it, rather than producing a bundle nobody can deploy. Workers builds are minified by default (unless `build.minify` is set), because bundle size is cold-start time; for the example bot that is about 60 KB, 20 KB gzip, the same as wrangler's own `--minify`. Without a target the plugin only hoists, for Vitest and custom setups. The example bot has one Vite config per target (`vite.config.ts` for Workers, `vite.node.config.ts`, `vite.bun.config.ts`), and `examples/bot/test/build.test.ts` runs the real `vite build` for each, starts the output as it would be deployed (Node and Bun processes, the Worker in Miniflare), and clicks through an Inline Handler View with signed requests. That proves hoisting holds in the bundle, not only under Vitest. Miniflare matches wrangler's version (5.x, which ships a newer workerd than Miniflare 4) and takes v4-style options through `convertV4MiniflareOptions`. A dev server for Node (serving the App through Vite's module runner with HMR), the tunnel, and dev Sync are the rest of the Dev Loop and come next.
