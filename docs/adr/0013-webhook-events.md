# Webhook Events: one handler of a decoded union, routed by path, never an error

Discord POSTs Webhook Events (app authorized, entitlement created, ...) to a separately configured URL, signed like Interactions (composure-rs ADR 0008). The App serves both from one entrypoint and routes by path: `eventsPath`, default `/events`, set on the root App's options, like Credentials. Signature, size and method checks are shared with Interactions, so a bad signature is 401 on either path. An Event Handler is one function, `app.events((c, event) => ..)`, whose `event` is a discriminated union over Discord's event types (`APPLICATION_AUTHORIZED`, `APPLICATION_DEAUTHORIZED`, `ENTITLEMENT_CREATE` / `_UPDATE` / `_DELETE`, `QUEST_USER_ENROLLMENT`), typed from discord-api-types, so `switch (event.type)` narrows `event.data`. composure-rs's per-event trait methods were rejected: a union is the idiomatic TypeScript form, and new events need no new method. Decoding checks each known event's essential fields; anything unknown or mismatched becomes `{ type: "unknown", raw }`, never an error, because repeated failures get Discord to disable the events URL. Every event, Discord's `PING` (type 0) and any body type this version does not know are ACKed with 204 at once. A type 1 event runs the handler as Background Work (before the 204 when the platform has no `waitUntil`), and handler errors are only logged, since the ACK is already sent. The handler's `c` is an `EventContext`, not an Interaction Context: it has `env`, `data`, `bot` and `waitUntil`, and no Interaction or Interaction Client. A bot has one events URL, so at most one App in a tree sets `events`, and a second is an `AppConfigError` naming both paths. A nested App's handler is used wherever it sits, so a shared module can carry the events into every platform's App that routes to it.
