# Wire Types come from discord-api-types and the vendored OpenAPI spec

composure-rs had to hand-write Discord's whole data model. In TypeScript, `discord-api-types` already describes Interactions, components and payloads, and `composurejs` imports it with `import type` only, so it costs nothing at runtime; it is a dependency for the published `.d.ts`, and core re-exports friendly aliases (`Interaction`, `User`, `Member`, ...) so bots rarely import it directly. REST request and response types are generated from Discord's OpenAPI spec (`discord/discord-api-spec`), vendored at a pinned commit, with `openapi-typescript`; only the ergonomic client methods are hand-written on top. A test checks every hand-written Endpoint's method and path against the spec, prints the routes not yet implemented, and checks that each `OUT_OF_SCOPE` prefix (gateway, OAuth2 user-token routes, partner SDK) still exists in the spec, with its reason. Values Discord may extend (component types, interaction types, Webhook Events) are handled as open unions with a raw case, never assumed exhaustive, so unknown data passes through instead of breaking a deployed bot.
