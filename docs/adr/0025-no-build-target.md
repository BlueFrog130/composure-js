# No build target: the plugins in the config decide the build

Amended by [ADR 0031](./0031-dev-loop-rebuilt.md): `composure()` takes `dev: { application, guild, tunnel }`.

`composure({ target })` is gone (it was ADR 0014's switch). What a bot builds is now the plugins its Vite config lists, and getting that list right is the bot's job, written once into its template. `composure()` hoists Inline Handlers, warns about placement, finds the App module (`app`), and runs the tunnel and dev Sync in `vite dev`, whatever else is in the config. `server()`, also from `@composurejs/vite`, is the Node and Bun build: an SSR bundle, `dist/index.js`, of the Default Server's generated entry (ADR 0024) or of `server({ entry })`, targeting `node22`, with every dependency bundled and `node:*` and `bun:*` external. In `vite dev` it serves the App itself. Node and Bun no longer differ: Bun runs the `node20` bundle and the Default Server, and the only Bun-specific setting (`bun:*` external) is harmless on Node. A Workers bot lists `cloudflare()` from `@cloudflare/vite-plugin` instead of `server()` and sets `build: { minify: true }` in its own config, as the template does. The plugin no longer checks that `@cloudflare/vite-plugin` is present or minifies for it, so neither plugin depends on the other's name or internals. The one link is between our own plugins: `server()` reads the App module from `composure()` through its plugin `api` and says so when `composure()` is missing, so `app` is configured once. The example bot keeps only its Workers config; `examples/bot/test/build.test.ts` builds `[composure(), server()]` through Vite's `build()` into `dist/server` and runs that bundle on Node and Bun. Rejected: inferring the target from whether `cloudflare()` is in `plugins` (inspects a third-party plugin by name, and a missed match silently builds the wrong thing); `composure({ server: true })` (the old target as a boolean); keeping `target` with `server()` as an alias (two ways to say one thing).
