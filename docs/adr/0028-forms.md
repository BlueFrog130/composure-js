# Forms: a modal's inputs defined once, its values typed and parsed from them

Amends [ADR 0015](./0015-inline-handlers-everywhere.md), where `onSubmit`'s values were typed only by annotation.

An annotation such as `(c, v: { why: number }) => ..` compiles whatever the inputs are, because TypeScript cannot read a modal's JSX children, so the types were a promise nothing kept. Text inputs also return only strings, so every numeric field was parsed by hand.

**What.** `form({ key: field.kind(..) })` defines the inputs. Every Field has a label (and optional description), is required unless `.optional()`, and knows its value type and what prefills it. `<Modal form={f} values={..} onSubmit={(c, v) => ..}>` renders one `<Label>` per Field after any `<Text>` children, and `Modal` is generic, so TypeScript infers `v` from `form`. Kinds: `text` → string; `integer` and `number` → number, parsed and checked against `min`/`max`, with a User Error naming the Field's label when the input is wrong (the handler does not run); `radio` → one Choice value; `select` and `checkboxes` → lists of Choice values; `checkbox` → boolean (never required, as in Discord); `user`, `role`, `mentionable`, `channel` → the resolved entities, prefilled by id; `files` → attachments. `.optional()` makes a value `T | undefined`, except lists, which come back empty. A select's `options={Choices}` types `onSelect`'s values the same way, and hand-written modals keep their annotations.

**Decoding travels with the modal.** A submit carries only each input's `custom_id` and value, and a modal may be submitted after a deploy. So a Field that decodes its value says how in its input's `custom_id`, after a `~`: `stars~n:1:5:Stars` (a whole number from 1 to 5, labelled "Stars"), `who~r` (resolve entities). `~` is therefore not allowed in a hand-written input's `name`. This is the same choice as Captures (ADR 0009, 0015): self-describing values instead of a registry that the code at submit time might not match.

**Rejected.** Inferring types from JSX children, which TypeScript cannot do. Standard Schema validation for now: Discord already enforces required, length and option membership, and numbers were the only parsing missing; it can be added to Fields later without changing their shape. Mixing hand-written `<Label>`s with a Form, which would leave some values untyped. Registering Forms by id so the submit could look up the definition, which breaks for modals opened before a deploy that changed the Form.
