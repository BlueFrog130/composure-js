# One core package with subpath exports, plus Vite tooling packages

As Hono does, the framework is one package, `composurejs`, whose main entry holds `App`, Context, dispatch, verification and errors, with subpath exports for everything a bot may not need: `composurejs/jsx-runtime` and `/jsx-dev-runtime` (for `jsxImportSource: "composurejs"`), `/components`, `/rest`, `/testing`, and one per Adapter (`/cloudflare`, `/node`, `/bun` in v0.1; Deno, Vercel, Netlify and Lambda later). Subpaths, zero runtime dependencies and `sideEffects: false` keep a Worker's bundle and cold start down to what it imports; a `size-limit` budget enforces it in CI. Core source is type-checked without Node types (`tsconfig.core.json`), so it cannot reach for `Buffer` or `node:*`; only the Node Adapter can. Tooling that only runs at dev or deploy time lives apart so it never reaches a bundle: `@composurejs/vite` (Dev Loop, Inline Handler hoisting, build targets) and `@composurejs/cli` (`composure sync [--plan] [--scope ..]`). Starter templates ship as `create-composurejs` (`pnpm create composurejs`), because `create-composure` is taken on npm by an unrelated project; `composurejs` and the `@composurejs/*` names were free when checked (2026-10-21) and should be reserved before the first publish. The repo is a pnpm workspace; packages are versioned independently with Changesets.
