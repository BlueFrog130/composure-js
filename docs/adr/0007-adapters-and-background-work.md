# Core owns the pipeline; Adapters only supply env, waitUntil and the entry point

Every Adapter shares one pipeline in core, `app.fetch(request, env?, platform?)` (also exposed as `handleInteraction` for custom routing and tests): cap the body (413 over 1 MiB); verify the Ed25519 signature over `timestamp || body` with WebCrypto (`crypto.subtle.verify("Ed25519", ..)`, on Workers, Node 20+, Bun and Deno, so no dependency), the public key imported once per isolate and cached in module scope, and the timestamp required to be within 5 minutes (401 otherwise); parse (400 if it is not an Interaction); answer Ping with Pong; run middleware and dispatch; render the Response or the Error Renderer's output; send responses carrying files through the callback endpoint (multipart, over the App's Transport) and answer 202. If Discord rejects that callback, the Interaction is still unanswered, so the HTTP response carries the generic error instead and the failure is logged with the route template, never the URL that holds the token. Webhook Events take the same entrypoint by path (`/events`), are ACKed with 204, and handled as Background Work (composure-rs ADR 0008).

An Adapter is then only how to get the Env and a Platform from the platform call, how to load Credentials and Bot Data once (ADR 0008), and what to export. On Cloudflare `export default app` already fits `fetch(request, env, ctx)`, and `ctx.waitUntil` runs Background Work (bounded to about 30s after the response). Node's `serve(app, { port })` wraps `node:http` in Web `Request`/`Response`, tracks Background Work promises and awaits them on SIGTERM for up to 30s, and answers `GET /health`. Bun's default-export object passes the server, not an env, as `fetch`'s second argument, so `composurejs/bun` wraps the App with `process.env` and the same promise tracking.

Background Work uses one mechanism everywhere: `platform.waitUntil(promise)` when present, otherwise (AWS Lambda, an untracked server) the fallback POSTs the deferred callback through REST, does the work, then answers the HTTP request with 202. Deferred Responses choose ephemerality at defer time because Discord fixes it then; the final edit retries briefly on 404 because Background Work can beat Discord registering the reply; `deferUpdate` failures go out as an ephemeral follow-up, since an edit would clobber the component message (composure-rs ADR 0006).
