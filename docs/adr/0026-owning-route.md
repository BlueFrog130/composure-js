# A click runs the middleware of the Command that rendered it (the Owning Route)

Amends [ADR 0015](./0015-inline-handlers-everywhere.md), under which every click and modal submit ran only the root App's middleware.

That rule made a guard on a nested App a trap: `new App().use(modsOnly).command(ban)` protected `/ban`, but not the buttons `/ban` answered with, which anyone who could see the message could press. Discord's `default_member_permissions` does not apply to components either. Everyone reads "the guard on `/ban`" as covering its buttons, so the framework now makes that true.

**How.** Each top-level Command has an Owning Route key: 5 base-36 characters of an FNV-1a hash of its type and name, so the key lasts as long as the Command does, whatever App it moves between. When an Interaction is routed to a Command, render adds the key to the `custom_id` of every handler it renders, after the Handler Id: `_Kq3vX9a~71ux6:i2ckt9ru6z01:n0`. The same applies to Views sent through `c.bot` and `c.client` while answering that Command (the clients carry the key), to deferred work, and to the Error Renderer's output. A click splits the key off, runs the Command's own middleware chain (outer Apps' first, as for the Command itself), and handlers rendered by that click keep the key, so a confirm step behind a guarded button is guarded too. A key no App lists any more (the Command was removed or renamed) gets the Fallback; it never falls back to the root middleware alone, which could be weaker. A `custom_id` without a key (sent outside any Command: a hand-built `BotClient`, a Webhook Event, a message from before this change) runs the root App's middleware, as before. Two Commands whose keys collide are an `AppConfigError` at build, naming both. A raw `customId` prop is the author's own string and is never changed.

The key costs 6 of the 100 characters, on every handler rendered under a Command, whether or not that Command has middleware of its own. Adding it only when there is extra middleware would save the characters, but middleware added later would then not cover buttons already sent.

`c.can(...flags)` and `c.appCan(...flags)` with the restated `Permission` flags make the common guard one line. `c.can` is false outside a server, and Administrator has every flag.

**Rejected.** Reading the Command from the message: `interaction_metadata` does not carry the Command's name, and `message.interaction.name` is deprecated. Explicit middleware per handler (`<Button use={[modsOnly]}>`), because forgetting it is the bug this fixes. Leaving the rule as it was and documenting it, for the same reason. Ambient context (AsyncLocalStorage) to find the route while rendering, which not every platform has; threading the key through render, the response and the clients works everywhere.
