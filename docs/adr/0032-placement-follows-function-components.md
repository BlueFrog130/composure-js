# The placement check follows function components, across modules

Amends [ADR 0023](./0023-static-placement-checks.md), which left "a component that returns a tag" to the render walk.

Most of a bot's markup goes through its own function components (`<ui.Primary>` wrapping a `<Container>`), so a check that stopped at them missed the common mistake: a `<Button>` given to a function component that puts its children in a `<Container>`. `checkPlacement` now works out, for each function component a View uses, what it renders at its top (its roots) and the parents it puts its `children` in (its slots), and checks both: a child against the slots, with the function component named (`<Button> cannot go inside <Container> (in <ui.Primary>)`), and the roots against where the function component is placed (`(rendered by <Card>)`). Children a function component returns as they are (`<>{children}</>`) are checked against its own parent. It follows arrow functions and `function` declarations at module scope; children read as `({ children })` or `props.children`, forwarded by a `{...props}` spread, or passed as a `children` prop; chains of function components; and every `return`. A function component that renders itself adds nothing. Function components are followed in the module and, through relative imports (named, default, namespace) and re-exports (`export { X } from`, `export *`, a default export, a directory index, `./x.js` for `./x.ts`), into other modules. Packages, path aliases, variables and anything computed stay with the render walk, which remains the authority. Core cannot read files (no Node APIs), so `checkPlacement(program, { file, load })` resolves specifiers as strings and asks the caller's `load(path)` for a parsed program. The Vite plugin's `load` reads and parses with oxc, cached by mtime, and calls `addWatchFile` on each module it followed, so an edit to `ui.tsx` re-checks the modules using it in `vite dev`. The lint rule does the same with `oxc-parser`, now a runtime dependency of `@composurejs/eslint-plugin` (ESLint gives a rule no parser for other files), and accepts two limits: imported modules are read as saved, not as the editor's unsaved text, and a module is re-checked only when it is linted again. Every message keeps the table's wording and adds a parenthesized note, and the tests render each static case from disk to require the walk to throw the same message without the note. A module is checked when it contains JSX even if it imports nothing from `composurejs`, since one can misplace a function component's tags (`<Bar><Primary /></Bar>`). Rejected: annotating function components (`@composure-wraps Container`), which still needs the imported module read and drifts from the code; checking same-module function components only, which misses the usual layout of components in their own file; resolving through Vite's or TypeScript's resolver, which the lint rule does not have.
