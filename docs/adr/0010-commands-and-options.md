# Commands are definition objects whose Options type the handler

composure-rs needed `#[command]` to derive a Command Definition and typed parameters from one function. In TypeScript the definition object does it: `command({ name, description, options: { user: option.user(".."), count: option.integer("..").optional() }, handler: (c, { user, count }) => .. })`. Each Option builder carries its value type and whether it is required (`Option<T, R>`), `.choices(defineChoices(..))` narrows `T` to the Choice values, and `OptionValues<O>` maps the record to the handler's second argument (required keys plain, optional keys `?:`). Options are keyed by name, which rules out duplicate names. Values arrive resolved: a User Option is the user with `member` and `displayName` merged in, and channels, roles, mentionables and attachments come from `resolved`. Required Options are sorted first in the definition, so Discord's ordering rule is applied rather than checked. Name, description, length, 25-Option, 25-Choice, min/max and choices-versus-autocomplete rules throw an `AppConfigError` naming the path (`Command "/x" option "Bad" ..`) when the Command is defined, so they fail at import in dev, in tests and in Sync alike.

Groups (`group({ subcommands: [..] })`) nest one level, as Discord does, and settings that only top-level Commands have (`contexts`, `integrationTypes`, `scope`, `defaultMemberPermissions`, `nsfw`) are rejected on subcommands. User and message context menu Commands (`userCommand`, `messageCommand`) get their resolved target as the second argument and share a name namespace only within their command type. Autocomplete is declared inline on the Option (`.autocomplete((c, input, others) => ..)`). It receives the focused partial input and the raw values of the other Options, may return Choices or bare values, and is cut to 25. A failing autocomplete is logged and answered with no suggestions, because a message is not a valid answer to it. An Interaction whose Options do not match the definition (usually a Command changed but not yet synced) throws `InvalidOptionsError`, which is logged as a warning and answered generically.

TypeScript cannot infer some type parameters while others are given explicitly, so `command<E>({ options })` would lose the Options' types. Instead, `createFactory<BotEnv>()` returns definers bound to one Env (`command`, `group`, `userCommand`, `messageCommand`, `middleware`, `app`), as Hono's factory does. Commands written without an Env have `c.data: unknown`, and their handlers are declared as methods, so they fit any App.
