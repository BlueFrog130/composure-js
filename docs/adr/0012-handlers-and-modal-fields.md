# Handlers outside render; modal values typed by a field schema, bound in markup

Not every handler belongs inside a View, and not every build has the Vite plugin (ADR 0005). `component(prefix, { state, handler })` defines a Component Handler whose Custom ID State is typed by Codecs (`p.*`). It is placed with `onClick={vote.id({ poll, up: true })}` (`onClick`, `onSelect` and `onSubmit` are `customId` under the name of the event), receives the select values for selects, and is listed with `app.component(..)`. `modal(prefix, { state, fields, render, handler })` defines a modal and its submit handler together: `feedback.open(state)` is the Output that opens the modal, and render's `<Modal>` gets its `customId` set for it. Both work with any compiler, the way composure-rs's `#[component]` and `#[modal]` do.

TypeScript cannot read submitted values from JSX children, so a field schema leads: `fields: { what: f.text(), severity: f.choice(Severity), notify: f.checkbox() }` types the handler's values. Markup binds an input with `<TextInput field={fields.what} />`, which sets the input's `customId` to the field name, sets `required` from the field (`.optional()` makes it `undefined`, or `[]` for list fields; a checkbox is never required), and fills defaults such as a radio group's options from the same `defineChoices` its Command Options use. The schema leads and the markup follows, so the render walk checks what composure-rs checked at compile time. Every field has exactly one input of a kind that can carry it (`f.choice` binds `<RadioGroup>` or `<StringSelect>`, ...), every input is a field, and an input bound by `field=` sets neither `customId` nor `required` itself; each violation is a `RenderError` naming both sides. A modal View (a View with `fields`, whose `<Modal onSubmit={on("send", (c, values) => ..)}>`) uses the same schema. On submit, values are read from Labels (and legacy Action Rows) by `custom_id` and parsed against the schema: a missing required value, a choice outside its Choices, or an unresolved file sends the Interaction to the Fallback, like undecodable state, rather than reaching the handler with values its types do not promise.

Component and Modal Handlers and Views share one namespace of `custom_id` prefixes, are wrapped by the middleware of the App that lists them (ADR 0011), and route by the text before the first `:`. An unknown prefix, an unknown handler name, or state that does not decode answers "This message is outdated." (ephemeral), logged at debug.
