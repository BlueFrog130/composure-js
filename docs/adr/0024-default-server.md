# A Default Server in the Vite plugin, not adapter packages

Amended by [ADR 0025](./0025-no-build-target.md): `server()` builds the Default Server and takes `entry`; there is no `target`. Amended by [ADR 0031](./0031-dev-loop-rebuilt.md): `serveInDev` lives in `server()`.

The three Adapter packages (ADR 0022) are gone. `@composurejs/adapter-cloudflare` was an identity wrapper (`export default app` already fits Workers), and `@composurejs/adapter-bun` only passed `process.env` and a Tracker, which Bun's `node:http` runs fine without a Bun-specific path. Only the Node server did real work: `node:http` to Web `Request`/`Response`, the body cap, `GET /health`, and draining Background Work on SIGTERM. That code now lives in `@composurejs/vite/server` (`packages/vite/src/server.ts`): the plugin already needed it for the Dev Loop, it already runs only on Node, and a bot already depends on the plugin, which bundles the server into `dist/index.js`, so it can stay a devDependency. For `target: "node"` and `"bun"` the plugin builds a generated entry, `virtual:composure/server`, which imports the App module (`app` option, default `src/app.tsx`, exported as `app` or default) and calls `serve` from that subpath: the Default Server. A bot that wants anything else (another port, no health check, Express, `Bun.serve`, Deno, a serverless handler) writes its own entry and names it with `entry`. That entry can reuse `serve`, `toRequest`, `send` and `onShutdown`, or call `app.fetch(request, env, platform)` with `createTracker()` from core, which is the whole contract (ADR 0007). New platforms with a fetch handler (Deno, Vercel, Netlify) need no package; one that needs real glue (Lambda) can get an exported helper next to `serve`. `vite dev` serves the App through the same `toRequest`/`send`, ignoring `entry`, so a custom entry affects the build only. Core stays free of Node code. The signed fixtures are replayed over `serve` in `packages/vite/test/server.test.ts`, and the example's build test runs both the Node and Bun bundles. Rejected: keeping `@composurejs/adapter-node` alone (a package and release for one function the plugin already ships); `composurejs/node` (Node code in core, ADR 0022); `Bun.serve` for the `bun` target (a second server to maintain, with no benefit at a Discord bot's request rate); generating nothing and requiring an entry file (boilerplate in every node and bun bot).
