# Routes are registered explicitly, by chaining on an App that nests

An App lists every Route it serves by chaining: `new App<Env>().command(cookie).route(admin).view(Card).events(events).onError(..)`. There is no auto-discovery (no `import.meta.glob` scan, no decorators collecting into a global): one list is both what dispatch answers and what Sync publishes, so it is obvious from the code what a bot serves, and forgetting a line means the Command is neither answered nor synced, which surfaces at once (composure-rs ADR 0001). Apps nest with `.route(subApp)`, so a module owns its own list and the root lists the module (composure-rs ADR 0013). Chaining was chosen over an object form (`app({ routes: [..] })`) because Hono users expect it and each call can extend the App's types (e.g. middleware Variables); an object form may be added later as sugar over the same calls. `fetch` is a bound property, so `export default app` works on platforms that call `fetch(request, env, ctx)`. Tree-wide rules (duplicate Commands per type and Scope, prefix collisions, at most one `onError` and one `events` per tree, Views placed but not listed) are checked when the tree is first built, at the first request or in `app.check()`, which the templates call in a test; they throw with the offending path. A file-based `import.meta.glob` helper may come later as sugar that produces the same chain; it must never be the default.
