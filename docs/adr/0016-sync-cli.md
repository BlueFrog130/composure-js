# Sync is a CLI, `composure sync`, that loads the App through Vite

composure-rs ran Sync from a bin the bot owned (its ADR 0002), because Definitions only existed after compiling the user's crate. In JavaScript, Definitions exist at runtime, and Vite can load any module with the bot's plugins applied, so Sync is a command: `composure sync` from `@composurejs/cli`. It imports the App's module (`--app`, default `src/app.tsx`, exporting the App as `app` or default) with Vite's `runnerImport` and `@composurejs/vite`, so modules with Inline Handlers compile exactly as in the build. The bot's `vite.config.ts` is not used: its platform plugins are for serving and building Workers, not for reading Definitions in Node. The App gives `app.definitions()`: each Command Definition with its Scope.

The semantics are composure-rs's. Each target (global, or one guild) gets every Command whose Scope maps to it. Commands without a Scope are global; `scope: "dev"` goes to the guilds in `COMPOSURE_SCOPE_DEV` (uppercased, `-` as `_`), and an unmapped Scope is an error naming the variable. Every listed guild is a target, so a guild whose Commands were all removed is cleared, and unlisted guilds are never touched. Guild targets drop the global-only `contexts`, `integration_types` and `dm_permission`. The Sync Plan compares by name and type against what Discord stores, ignoring the defaults it fills in (`null`s, `required: false`, `nsfw: false`, empty lists, `1.0` bounds, ids). `contexts` and `integration_types` are compared only when the Command sets them, since Discord fills them from the app's settings. Targets with changes are overwritten with one bulk `PUT` each, which creates, updates and deletes atomically; the others are left alone. Sync waits out rate limits of up to 60 seconds, because it runs at deploy time, not inside a request (ADR 0006). `--guild <id>` sends everything to one guild to try a bot out.

Credentials come from `DISCORD_TOKEN` and `DISCORD_APPLICATION_ID`, defaulting to the id a bot token starts with, so one secret is enough. They are read from the process environment, over Vite's `.env` files for `--mode` (default `production`), over `.dev.vars` (wrangler's secrets file), so Workers and Node projects both work without extra setup. It never syncs silently. `--dry-run` shows the plan, and `--check` also exits 2 when Discord is out of date, for CI. In a terminal it asks before applying, warning about deletions; outside one it applies only with `--yes`, so a forgotten flag cannot change Discord from CI. `--yes` cannot be combined with `--dry-run` or `--check`. Exit status: 0 synced or up to date, 1 failed or cancelled, 2 out of date.

The command line is commander (parsing, help, `--version`, conflicting flags), and the output is `@clack/prompts`: intro, a spinner per step, the plan in a note with creates, updates and deletes colored, a confirm, and an outro or a cancel line. clack is the JavaScript original of the `cliclack` crate composure-rs used. The output goes through a small `Ui` interface, so tests record what a user would see instead of scraping a terminal. The library half (`plan`, `apply`, `targets`, `formatPlan`, `configFromEnv`, `loadApp`) is exported for custom deploy scripts. Dev Sync on file change (part of the Dev Loop) will call the same `plan` / `apply`.
