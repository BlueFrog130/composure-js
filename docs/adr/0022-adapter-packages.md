# Adapters are their own packages

Superseded by [ADR 0024](./0024-default-server.md): there are no adapter packages.

Each Adapter is a package, `@composurejs/adapter-<platform>` in `packages/adapter-<platform>` (`cloudflare`, `node`, `bun`; Deno, Vercel, Netlify and Lambda later), replacing core's `/cloudflare`, `/node` and `/bun` subpaths (ADR 0002). Core then holds no Node code at all, so `tsconfig.core.json` checks all of `src` with no exclusions, and an Adapter can version and release on its platform's schedule (a Node or Bun API change) without a core release. An Adapter depends on `composurejs` with `workspace:^` (a caret range on publish): a regular dependency rather than a peer, because Changesets bumps a peer-dependent to the next major whenever the peer leaves its range, which in 0.x is every minor of core; package managers dedupe it with the bot's own `composurejs` when the ranges agree. What the Adapters share stays in core, platform-neutral: the Tracker (`createTracker`, Background Work for long-running servers) is exported from `composurejs`, and `MAX_BODY_BYTES` already was. `onShutdown` needs `process` and is fifteen lines, so `adapter-node` and `adapter-bun` each keep a copy instead of one depending on the other or a third internal package. The signed fixtures stay in core's tests; `test/replay.ts` replays them over `app.fetch` there and over each Adapter's entry point in that package's `test/regression.test.ts`, so core never depends on an Adapter. `@composurejs/vite` bundles `adapter-node` for the Dev Loop's `toRequest`/`send`, as it bundles core. Templates depend on their target's Adapter; the Workers template needs none, since `export default app` fits. Rejected: keeping subpaths (one release train, Node code in core); a single `@composurejs/adapters` package with subpaths (same coupling, just moved).
