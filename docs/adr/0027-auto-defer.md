# Auto Defer: a slow handler is deferred for it, on by default

Discord gives an Interaction 3 seconds, and missing them shows "This interaction failed" with nothing in the bot's logs to say why. `c.defer` (ADR 0007) solves it only for handlers their authors know are slow; on serverless platforms, a cold start, a slow database or a REST call can make any handler slow on some requests. So composurejs defers for the handler when it has not answered in time.

**What happens.** `app.fetch` notes when the request arrived. If the handler (with its middleware) has not answered 2 seconds later (`autoDefer: { after }` on the App), the HTTP request is answered with a deferral: type 5 for a Command or a modal submitted from a Command, type 6 for a click or a modal submitted from a message. The handler keeps running as Background Work, and its answer is delivered then: a message edits the loading reply; markup from a click edits the clicked message; `c.reply(..)` from a click follows up; a handler that called `c.defer` itself runs its work as usual. On platforms without `waitUntil`, the deferral goes through the callback endpoint and the answer follows before the HTTP request gets its 202, as for `c.defer`. Autocomplete and Ping are never deferred.

**Ephemerality.** Discord fixes it with the loading reply, before the answer exists. The Auto Defer is public; if the answer is ephemeral, the loading message is deleted and the answer goes out as an ephemeral follow-up, and a warning names `autoDefer: "ephemeral"`, which a Command whose answers are private sets to defer privately instead. A private loading reply followed by a public answer stays private. A `<Modal>` cannot follow a deferral at all; that is an error shown through the Error Renderer, naming the fix (open the modal first, or `autoDefer: false` on that Command).

**Settings.** `new App({ autoDefer: false })` turns it off; each definer takes `autoDefer: false | "ephemeral"`. A Group's applies to its subcommands unless they set their own, and a Command's applies to clicks it owns (its Owning Route, ADR 0026), so `false` keeps a modal-opening button undeferred.

**Rejected.** Off by default: the failure it prevents is the most common one on serverless, and it only shows in production. Deferring every Interaction at once: every answer would cost a REST call and the loading flicker. A shorter threshold: cold starts are not counted (the timer starts in `app.fetch`), and the reply still has to reach Discord, so 2 seconds leaves room. Ephemeral by default: most answers are public, and a private loading reply cannot become public.
