# A custom JSX runtime builds Discord component JSON; placement is checked at render

Views are written in JSX with `jsxImportSource: "composurejs"`, compiled by whatever already compiles the bot (Oxc in Vite, tsc, esbuild). `composurejs/jsx-runtime` builds a plain tree of tagged nodes and render turns it into Discord's component JSON: no virtual DOM, no reconciliation, no hooks and no signals, because Discord keeps no client state and every click is a new Interaction. Built-in tags are exported PascalCase functions (`Container`, `Section`, `Text`, `Row`, `Button`, ..., the same names as composure-rs, `Row` being an Action Row) rather than lowercase intrinsics, so each has import completion, go-to-definition and a TSDoc'd props interface that doubles as the tag reference. TypeScript gives every JSX expression the type `JSX.Element` and never learns what a child is, so placement cannot be type-checked; instead render performs one validation walk that checks placement (naming both sides: "`<Container>` cannot go inside `<Container>`", "text cannot go in a `<Row>`") together with Discord's Limits (40 components, 4000 characters of text, 5 buttons per row, 25 options, 100-character `custom_id`, 80-character labels, no `content`/`embeds` on a Components V2 message), and throws an error naming the rule, since a callback Discord rejects shows "This interaction failed" and logs nothing. `view.check()` runs the same walk in tests; a lint rule for static cases may follow. JSX collapses newlines and trims lines but Discord markdown is line-based, so each `<Text>` is one block, `<br />` emits `\n`, and an `` md`..` `` tagged template keeps raw markdown; this is documented prominently. Children may be strings, numbers, `null`/`false`/`undefined` (nothing), arrays and iterables, nested Views, and promises (async Views), which render awaits. Adjacent text and `{expr}` children inside `<Text>` join into one Text Display.
