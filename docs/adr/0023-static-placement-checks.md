# Placement is also checked statically: Vite warnings and a lint rule, from one table in core

ADR 0004 left placement to the render walk because TypeScript gives every JSX expression the type `JSX.Element`, so a parent's `children` cannot tell a `<Button>` from a `<TextInput>`. Finding a misplaced tag only when the View renders, often only when a click reaches it, is late, so placement is now checked before render twice: `@composurejs/vite` warns in `vite dev` and `vite build` (`file:line:col: <Button> cannot go inside <Container>`; `composure({ placement: false })` turns it off), and `@composurejs/eslint-plugin` reports it in the editor through one rule, `@composurejs/placement` (an error in `configs.recommended`), which oxlint loads unchanged as a JS plugin. Both run `checkPlacement` from `composurejs/placement` over the module's ESTree program (oxc's in the plugin, which parses each module once for this and Inline Handler hoisting; ESLint's or oxlint's in the rule). It knows tags imported from `composurejs` or `composurejs/components`, renamed or as a namespace, and follows children through fragments, `&&` / `||` / `??`, `? :`, arrays and `.map(..)` callbacks. Anything else, such as a component that returns a tag, or a variable, is left to the render walk, which remains the authority. The table (`PLACEMENT`, `placementError`) lives in core next to the walk, and the walk's messages come from the same wording. `test/placement.test.tsx` renders every built-in tag, text and `<br />` inside every parent in the table and requires the walk to throw exactly the table's message or no placement error, so the two cannot drift. The subpath adds nothing to a bot's bundle, since only tooling imports it. Rejected: a function-call API instead of JSX (TypeScript could type it, but it gives up JSX); a TypeScript language service plugin (editor-only, and `tsc` and CI ignore it); branded `JSX.Element` types (TypeScript widens every JSX expression to `JSX.Element` anyway); counting rules (`A <Row> holds at most 5 <Button>s`) in the static check (most rows are built with `.map`, so the count is rarely static).
