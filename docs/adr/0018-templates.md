# Starter templates come from one generator and are built and tested in CI

`pnpm create composurejs [dir]` (`create-composurejs`, since `create-composure` is taken; ADR 0002) scaffolds a bot for Cloudflare Workers, Node or Bun. The three templates are one generator, `generate(template, name, versions)`, not three directories, because they share almost everything: the App (`/ping`, `/greet` with a typed Option, a `/counter` with Inline Handlers), its tests, `tsconfig.json` (`jsxImportSource: "composurejs"`), `vitest.config.ts` (the plugin without a target, so tests compile handlers but never start the Dev Loop), `.env.example`, `.gitignore` and the README. They differ only where the platform does: the Vite config (`@cloudflare/vite-plugin` with `wrangler.jsonc`, or a `node`/`bun` build target), the entry, and `deploy` versus `start`. A duplicated directory would drift; the generator cannot. The CLI follows `composure sync`'s shape (ADR 0016): commander for the arguments (`[dir]`, `--template`, `--no-install`, `--yes`) and `@clack/prompts` for the questions, asked only in a terminal, with defaults (`my-bot`, `cloudflare`) otherwise. It refuses a non-empty directory unless confirmed, and installs with the package manager that ran it. The versions it writes are the sibling packages' versions at build time, bundled into the bin, so a release scaffolds what it was released with. `scripts/check-templates.mjs` is composure-rs's `check-templates.sh`: after `pnpm build` it generates every template into `.tmp/templates/`, points its composurejs packages at the workspace with `link:`, and runs `pnpm install`, `typecheck`, `test` and `build`. CI runs it, so what a new user gets is proven to work at every commit.
