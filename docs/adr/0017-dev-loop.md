# The Dev Loop is `vite dev`: serve, tunnel, repoint only the dev application, sync to a dev guild

The kickoff brief asked for one command from clone to clicking buttons in Discord. Discord can only reach a public HTTPS URL, checks it with a signed PING before accepting it, and only shows Commands that were synced. So `vite dev`, with `composure({ target })`, does four things.

**Serving.** For `node` and `bun` the plugin serves the App itself (`appType: "custom"`): POST requests go to the module's `app` (or default) export, imported through Vite's ssr module runner on every request. An edit takes effect on the next Interaction without a restart, and Inline Handlers re-register under the same ids. Background Work runs on a tracker, and `GET /health` answers. For `cloudflare`, `@cloudflare/vite-plugin` already serves the Worker on workerd from the same port, so the plugin only adds the rest.

**Tunnel.** Once the server listens (Discord PINGs a new endpoint immediately, so it must already answer), the plugin opens a cloudflared quick tunnel through `untun`, which downloads cloudflared on first use under Cloudflare's terms, and logs the URL. `dev.startTunnel(port)` swaps in another (ngrok, a fixed hostname), and the tunnel closes with the server. It is on when `COMPOSURE_DEV_APPLICATION_ID` is set, or with `dev.tunnel: true`.

**Repointing the endpoint, guarded.** The plugin PATCHes `/applications/@me` with `interactions_endpoint_url: <tunnel>/interactions` only when `COMPOSURE_DEV_APPLICATION_ID` equals the token's application id. Naming the application is the developer saying "this one is my dev application"; a production token in `.env`, or a mismatch, never repoints anything, and the URL to set by hand is printed instead. The brief's rule, a separate dev application and never a prod one, becomes something that can't happen by accident.

**Dev Sync.** When `COMPOSURE_DEV_GUILD` is set (or `DISCORD_GUILD_ID`, as composure-rs's tests used), every Command goes to that one guild on start and after each source change (debounced 300 ms). That is the CLI's `--guild` mode with no prompt, and guild Commands update instantly, unlike global ones. Definitions are read by loading the App through Vite with a fresh plugin instance, as the CLI does (ADR 0016). A change that leaves the Definitions as they were sends nothing, and failures are logged without stopping the server. The Sync library moved into core (`composurejs/sync`) so the CLI and the plugin share it without depending on each other.

Configuration is read like the rest of the toolchain: Vite's `.env` files for the mode, under the process environment. The Dev Loop only runs when the plugin has a `target`, because Vitest serves the plugin too, and a test run must never reach Discord with a developer's real token. Not built yet: auto-installing the guild install link, and Webhook Events URL repointing (the same PATCH, `event_webhooks_url`).
