# Credentials and Bot Data are typed values, loaded once per isolate at the edge

Core never reads configuration itself: it takes `Credentials` (`{ publicKey, token?, applicationId? }`) as a value (composure-rs ADR 0014). `new App({ credentials })` accepts either the value or a loader `(env) => Credentials | Promise<Credentials>`; without one it reads the conventional names (`DISCORD_PUBLIC_KEY`, `DISCORD_TOKEN`, `DISCORD_APPLICATION_ID`) from the Env with `credentialsFromEnv`, which is only a lookup over a record, so it works on Workers (`env`) and Node and Bun (`process.env`) alike. Bot Data, the bot's own typed configuration, is built by `new App({ data: async env => .. })` and read as `c.data`, typed by the App's `Env` generic. On Workers the Env only exists per request, so both loaders run on the first request of an isolate and are cached; a failing loader answers 500, is logged, and is retried on the next request instead of caching the failure. Loaders belong to the root App; a nested App's are ignored with a warning at build. `c.bot` exists only when the Credentials carry a token. Sync takes its own configuration (token and application id, no public key).
