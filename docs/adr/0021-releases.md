# Releases: Changesets, independent versions, provenance

The published packages are `composurejs`, the Adapters (`@composurejs/adapter-*`, ADR 0022), `@composurejs/vite`, `@composurejs/cli` and `create-composurejs`; `examples/bot` and `docs` are private. They version independently with Changesets, as the kickoff brief asked: a fix to the CLI should not bump core. composure-rs used one shared version (knope) because its crates were tightly coupled through macros; here the coupling is through ordinary semver ranges (`workspace:^` becomes a caret range on publish). `create-composurejs` bundles its siblings' versions at build time, so it scaffolds what it was released with (ADR 0018). Every change to a published package carries a changeset (`pnpm changeset`). On `main`, `.github/workflows/release.yml` runs the tests and then `changesets/action`, which keeps a "Version Packages" PR up to date (versions and changelogs); merging it builds and publishes with npm provenance. Packages ship only `dist`, their `package.json` and the LICENSE, copied in `prepack`. The license is Apache-2.0, matching composure-rs. The `@composurejs/source` export condition stays in the published `exports`; it points at `src/`, which is not shipped, and is only used inside this workspace. The first release (0.1.0 of each) is the pending `initial-release` changeset; the npm names must be reserved first.
